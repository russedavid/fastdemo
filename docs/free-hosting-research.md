Frontline free-hosting research — September 7, 2026
================================================

**Recommendation: start with alwaysdata Free for the FastHTML application and Groq Free for inference.** This is the most promising route to a public demo with persistent data and no monthly bill, while preserving most of the current application. Use Railway Free as the first alternative if alwaysdata's resource limits or database behavior fail a deployment test. Use Modal when controlling the model runtime becomes more important than using a hosted model API.

This is a researched deployment recommendation, not a claim that Frontline has already been deployed or that any provider has passed our application tests. Public pricing, documentation, provider support forums, and firsthand community accounts were checked. No accounts were created, cloud resources provisioned, credentials used, or inference requests made during this research. Free allowances describe current offers; account eligibility and actual cold-start times still need verification.

The comparison covers 30 hosting routes, followed by inference and storage options. Its priorities are: a public URL that visitors can open without the owner intervening; a recurring free offer; data that survives restarts; compatibility with this Python app; and manageable changes. A cold start is acceptable. An expired trial, an administrator-only restart, or a page that silently loses everyone's uploads is a different limitation.

Frontline's actual requirements
------------------------------

The repository at commit 68aaa02 runs FastHTML/Starlette through Uvicorn, with HTMX in the browser. Its database is a local SQLite file accessed through FastLite; images, audio, and text are written under a local uploads directory. Hosting only the HTML does not run the application.

The current UI still calls the legacy OpenAI and Moondream integrations in ai_services.py. The improved report component in reporting.py has been tested separately against local Ollama. Hosting the UI will not, by itself, enable free report generation, transcription, or image processing.

A read-only measurement of the existing local preview found approximately **63 MiB resident memory** while idle. The lightweight application environment occupies about **73 MiB** on this Mac, excluding a local model and the optional Moondream dependency. These are encouraging observations for a small host, not Linux peak-memory or deployment-size benchmarks. Uploads and image decoding can use considerably more memory.

The locally tested Qwen 3.8 27B model occupies roughly 18 GB just for its quantized weights. The ordinary free web-service instances below cannot host that model alongside the app. An external inference service, an on-demand GPU, or a different model is necessary. Previous local report-generation timings are not estimates of hosted performance.

The shortest route to a useful public demo
-----------------------------------------

**alwaysdata is unusually compatible with the current architecture.** Its Free plan includes 256 MB RAM, one-quarter CPU, 1 GB disk space, and three days of backups. Disk allowance includes application files, databases, and other account data. The plan is restricted to noncommercial use and the supplied alwaysdata.net address. That makes it a candidate for a personal portfolio demo, rather than a paid customer service. [Plan specification](https://help.alwaysdata.com/en/docs/admin-billing/billing/public-cloud-prices/).

The platform explicitly documents ASGI applications running through Uvicorn as a “User program.” We can retain the FastHTML interface and investigate keeping SQLite and uploads in the account's persistent filesystem. There is no need to rewrite the UI in Gradio or JavaScript. [Python/ASGI deployment](https://help.alwaysdata.com/en/docs/web-hosting/languages/python/configuration/), [user-program configuration](https://help.alwaysdata.com/en/docs/web-hosting/sites/http-servers/user-program/).

It also documents precisely the requested sleep behavior: an application can stop after configurable inactivity and restart when an HTTP request arrives. It does not promise a particular startup latency. Separately, a new free account must log into its administration interface at least every 120 days; that interval becomes longer for older accounts. [Idle behavior](https://help.alwaysdata.com/en/docs/web-hosting/sites/misc/), [account inactivity policy](https://help.alwaysdata.com/en/docs/admin-billing/profile/alerts-notifications/).

**Groq is the best inference candidate found for this particular app.** Its current catalog includes Qwen 3.8 27B with text and image inputs. This is the same named model family/version as our local experiment, but Groq uses a different execution and numerical implementation, so our quality results must be rechecked there. The model is currently marked Preview. [Model documentation](https://console.groq.com/docs/model/qwen/qwen3.8-27b).

Groq's published Free limits list Qwen 3.8 27B at 30 requests/minute, 1,000 requests/day, 8,000 tokens/minute, and 200,000 tokens/day. Whisper transcription is also listed. All applicable limits matter: 1,000 requests/day does **not** mean 1,000 substantial reports/day. At an illustrative 5,000 total tokens per report, the daily token allowance would cover at most roughly 40 reports before other model use; actual token accounting and account limits must be measured. [Free rate limits](https://console.groq.com/docs/rate-limits).

Qwen 3.8 supports Groq's strict JSON-schema output mode. That should help preserve the report contract, while our own validators must still check source identifiers and business rules. Schema compliance does not establish factual correctness. Groq documents Free as a distinct tier from its paid Developer offering. [Structured outputs](https://console.groq.com/docs/structured-outputs), [billing](https://console.groq.com/docs/billing-faqs).

The proposed flow is straightforward: a browser visits Frontline on alwaysdata; the app saves notes and uploads; the app calls Groq from the server; the validated report and its source snapshot are saved and displayed. Visitors should be able to browse a clearly labeled completed example immediately, and choose to generate a new report. Live generation should show progress and an honest quota/unavailability message. A saved example must never be presented as a new model response.

The initial deployment experiment should establish:

1. A clean Linux environment fits the host's disk and memory limits without installing local model weights or an unnecessary vision stack.
2. SQLite transactions, concurrent requests, session persistence, and uploads survive a process restart. Persistent storage availability is not a substitute for testing our database's locking behavior.
3. A new visitor can open the URL after a full day without traffic and without an owner login. Measure first response, usable interface, and first generated report separately.
4. The five existing report development cases run through Groq, with raw responses and validation outcomes saved separately from the local Ollama runs.
5. Audio transcription and image processing are either connected to verified free capabilities or clearly unavailable. Groq image input is not automatically a replacement for every existing Moondream feature, including bounding boxes.
6. Demo sessions are isolated, uploads are bounded and expired deliberately, and API quotas are enforced server-side. A publicly shared login must not expose other visitors' files or let one visitor erase their work.

These are specific deployment acceptance checks, not reasons to redesign the entire portfolio.

Modal is especially relevant if we want to keep our own quantized model artifact. As an **illustrative calculation, not a benchmark**, its listed L4 GPU price is $0.000222/second. Suppose each isolated demo session holds one L4 for three minutes including initialization and idle tail, with two physical CPU cores and 32 GiB host memory. Listed rates yield about $0.0575 per session, or $5.75 for 100 such sessions, before other charges. Model loading, VRAM fit, achievable throughput, and actual idle billing need measurement. A 24 GB GPU may or may not have enough headroom for the selected runtime and context; a larger GPU changes this estimate. [Resource rates](https://modal.com/pricing).

Modal currently requires a payment method. It documents both a gross workspace usage budget and a separate net spend limit after credits. Configure a zero out-of-pocket spend limit where supported and a conservative gross usage cap within the recurring allowance; verify enforcement in the account before relying on it. The default can permit paid overage. For long generation jobs, use submit/status/result endpoints rather than assuming one uninterrupted request: Modal documents a 150-second HTTP limit followed by result redirects. [Billing](https://modal.com/docs/guide/billing), [budgets](https://modal.com/docs/guide/budgets), [long requests](https://modal.com/docs/guide/webhook-timeouts).

What the forums changed
-----------------------

Forum posts were used as reports of specific experiences and leads for further checking, not as representative uptime studies or substitutes for current terms.

- A July 9, 2026 Hugging Face user reported a new account could select ZeroGPU but not CPU Basic, with Docker marked paid. Current official documentation independently confirms the creation restriction. This removed ordinary HF Docker Spaces from the free shortlist. [Discussion](https://discuss.huggingface.co/t/new-free-accounts-cannot-create-cpu-basic-gradio-spaces-only-zerogpu-available/177629/1).
- An August 20, 2026 Oracle user reported an existing A1 VM disabled after resource-limit changes. The current documentation was checked rather than carrying forward the widely repeated 4-OCPU/24-GB figure. Individual grandfathered or paid-account entitlements need separate confirmation. [User report](https://community.oracle.com/CustomerConnect/discussion/974688/always-free-a1-instance-disabled-request-re-enable-to-resize-to-2-ocpu-12-gb).
- Render users reported disappearing uploads and 30–60-second startup delays. Provider staff explained the ephemeral filesystem and free-instance sleep behavior. The current docs, rather than those historical timings, determine the recommendation. [Uploads thread](https://community.render.com/t/nodejs-image-problem/23126), [startup thread](https://community.render.com/t/slow-startup-time-of-backend-application/19394).
- A firsthand alwaysdata recommendation described using SQLite on its free hosting, and a Django discussion led its author to choose alwaysdata. These are encouraging but old and not FastHTML concurrency tests. The current 1 GB allowance comes from provider documentation, not those older posts' 100 MB figure. [SQLite user's experience](https://www.reddit.com/r/webhosting/comments/115cjfk/), [Django discussion](https://www.reddit.com/r/django/comments/10ivtmr/).
- Northflank's own marketing article says no credit card is needed, while its billing documentation says all users must add a payment method before creating resources. Treat payment verification as required until the actual signup flow establishes otherwise. This disagreement is why the comparison does not call Northflank a verified card-free option. [Marketing claim](https://northflank.com/blog/how-to-deploy-vibe-coded-v0-apps-to-production), [billing requirement](https://northflank.com/docs/v1/application/billing/pricing-on-northflank).

The recommendation and the next useful change
---------------------------------------------

**Build the first deployable version for alwaysdata + Groq.** It offers the shortest plausible path from this repository to a persistent, interactive public demo with live report generation. Keep the provider adapter small, retain the report validator, and measure the deployment before selecting it permanently.

Railway is the next choice if preserving the filesystem architecture is the priority and alwaysdata fails its acceptance test. Northflank is attractive if we choose to migrate the database anyway. Cloud Run is the preferred mainstream container option for that same architecture, subject to a complete zero-dollar resource configuration. Modal is the inference-serving alternative when runtime ownership is itself part of the portfolio evidence.

The first implementation should produce one reviewable deployment package: explicit data paths, a lightweight install, persistent sessions, isolated synthetic demo workspaces, Groq report/transcription adapters, bounded uploads, and a measured cold-start/restart test. No provider signup, paid subscription, or public deployment was performed as part of this research.
